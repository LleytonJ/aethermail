## Context

AetherMail 是一个基于 Tauri 的跨平台邮件客户端，使用 Vue 3 + TypeScript 前端和 Rust 后端。

当前状态：
- `AddressInput.vue` 组件接收 `string[]` 类型的地址列表
- 用户输入后按 Enter/Tab/逗号时，整个输入内容被当作单个地址添加
- 不支持带显示名称的邮箱格式
- 后端 SMTP 客户端（lettre 库）已支持 `"名称" <email>` 格式

约束：
- 需要向后兼容现有草稿数据（存储的是 `string[]`）
- 后端无需改动，前端只需正确格式化地址字符串

## Goals / Non-Goals

**Goals:**
- 支持多地址批量输入（逗号、分号、换行分隔）
- 支持带显示名称的邮箱格式解析
- 解析失败时提供清晰的错误反馈
- 保持现有功能和用户体验的流畅性

**Non-Goals:**
- 不修改后端 SMTP 发送逻辑
- 不修改数据库存储结构（草稿仍存储为字符串数组）
- 不支持复杂的地址列表格式（如从 Excel 复制的表格数据）

## Decisions

### 决策 1：数据结构设计

**选择**: 使用 `EmailAddress` 接口替代 `string`

```typescript
interface EmailAddress {
  email: string    // 纯邮箱地址（必填）
  name?: string    // 显示名称（可选）
}
```

**理由**:
- 保留显示名称信息，提升邮件专业性
- 类型安全，便于扩展（未来可添加其他字段如 `type: 'to' | 'cc' | 'bcc'`）
- 草稿存储时可选择存储完整格式或仅存储邮箱

**备选方案**:
- 继续使用 `string[]`，发送时解析 → 无法保留显示名称信息，不符合需求

### 决策 2：解析时机

**选择**: 在所有输入终止点触发解析

| 时机 | 处理方式 |
|-----|---------|
| 粘贴 | 解析粘贴内容，分割地址 |
| 输入 `,` 或 `;` | 触发解析（先截取分隔符前的内容） |
| Enter / Tab | 触发解析 |
| 失焦 | 触发解析 |

**理由**:
- 覆盖所有用户输入场景
- 即时反馈，用户体验流畅
- 避免遗漏地址

### 决策 3：错误处理策略

**选择**: 全部拒绝策略

当解析结果包含任何无效地址时：
1. 不添加任何地址
2. 显示错误提示：`无效的地址: xxx, yyy`
3. 保留输入内容，让用户修正

**理由**:
- 避免部分地址丢失导致的发送错误
- 用户可以清楚知道哪些地址有问题
- 符合"要么全部成功，要么全部失败"的原子操作原则

**备选方案**:
- 添加有效地址，忽略无效地址 → 用户可能不知道某些地址被忽略，导致邮件发送给错误的人

### 决策 4：地址格式化策略

**选择**: 发送时转换为 SMTP 格式字符串

```typescript
function formatAddressForSend(addr: EmailAddress): string {
  if (addr.name) {
    return `"${addr.name}" <${addr.email}>`
  }
  return addr.email
}
```

**理由**:
- 与后端 lettre 库兼容
- 符合 RFC 5322 标准
- 显示名称用双引号包裹，避免特殊字符问题

### 决策 5：草稿兼容性处理

**选择**: 双向转换

- **读取草稿**: `string[]` → `EmailAddress[]`（name 为 undefined）
- **保存草稿**: `EmailAddress[]` → `string[]`（使用格式化函数，保留名称信息）

**理由**:
- 不破坏现有数据格式
- 新功能向后兼容
- 显示名称信息得以保留

## Risks / Trade-offs

### 风险 1：复杂地址格式解析错误

**风险**: 某些非标准格式的地址可能无法正确解析

**缓解**: 
- 使用宽松的正则匹配
- 提供清晰的错误提示，引导用户修正
- 记录解析失败的格式，后续迭代优化

### 风险 2：大数据量粘贴性能

**风险**: 粘贴大量地址（如 100+ 个）可能导致解析延迟

**缓解**: 
- 解析函数使用高效的正则和数组操作
- 如有性能问题，可添加防抖或 Web Worker

### 风险 3：现有数据兼容性

**风险**: 现有草稿和联系人数据使用 `string[]`

**缓解**: 
- 在组件加载时进行类型转换
- 保存时转换回字符串数组
- 添加单元测试验证兼容性
