## Context

当前邮件详情页面有删除按钮，但没有绑定实际功能。用户只能通过删除账户来清除邮件。需要实现单封邮件删除功能，涉及：
- 后端 SQLite 数据库删除
- Tauri 命令暴露给前端
- 前端服务调用和状态管理

现有架构：
- `database.rs` 已有 `delete_emails_by_account` 方法（批量删除）
- `commands/email.rs` 已有 `delete_account_emails` 命令
- `mailbox.ts` store 管理邮件列表和选中状态

## Goals / Non-Goals

**Goals:**
- 实现单封邮件删除功能（数据库 + 后端命令 + 前端调用）
- 删除后自动更新邮件列表 UI
- 同时删除邮件关联的附件（CASCADE）

**Non-Goals:**
- 不实现 IMAP/POP3 服务器端删除（仅本地删除）
- 不实现回收站/归档功能（简单删除即可）
- 不实现批量删除（单封邮件删除）

## Decisions

### 1. 数据库删除方式
- **选择**: 直接删除邮件记录，利用外键 CASCADE 自动删除附件
- **原因**: SQLite 的 `ON DELETE CASCADE` 已在 attachments 表定义，删除邮件时附件自动清理
- **替代方案**: 手动删除附件记录，但 CASCADE 更简洁可靠

### 2. 前端删除流程
- **选择**: 点击删除 → 确认对话框 → 调用后端 → 更新本地状态 → 清空选中
- **原因**: 需要用户确认防止误删，删除后立即更新 UI 避免显示已删除邮件
- **替代方案**: 不显示确认对话框直接删除，但用户体验差

### 3. 删除后邮件列表处理
- **选择**: 从本地 emails 数组移除，不重新加载整个列表
- **原因**: 性能更好，避免不必要的数据库查询
- **替代方案**: 重新调用 loadEmails，但增加延迟

## Risks / Trade-offs

- **误删风险** → 使用确认对话框，显示邮件主题
- **钓鱼邮件删除** → 删除按钮已存在，仅需绑定功能
- **服务器同步问题** → 本地删除不会同步到邮件服务器，下次同步会重新下载（文档说明即可，非技术问题）
